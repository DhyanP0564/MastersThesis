This appendix describes the software and how to regenerate the results.

The code is \texttt{pihm}, a Python package written for this thesis and released at \url{\pihmrepo}.\todo{create the repository, set the URL in 0\_packages.tex} The repository holds the library, the test suite, the documentation and the campaign files that define every run behind the thesis's numbers.

\paragraph{Software.}
\texttt{pihm} is written in Python 3.11 on NumPy \cite{harris2020numpy} and SciPy \cite{virtanen2020scipy}, with Qiskit and Qiskit Aer \cite{qiskit2024} for the circuits and their simulation. It builds a benchmark problem, assembles its residual in the standard or the descriptor form, compiles the block-encoding and \gls{gqsp} circuits, verifies them against the assembled operators, and prepares and decodes the ground state. Each concept has one implementation shared by both forms and every problem, and each claim the thesis makes has a test that recomputes it. Full API documentation is available.

\paragraph{Production.}
\label{app:software-campaigns}
A campaign is a YAML file listing a grid of problems, resolutions and options. Production ran $\res{production}{campaigns}$ campaigns, $\res{production}{hours}$ hours of computation in all, on the Setonix supercomputer \cite{pawsey2023setonix}, one node of the work partition per job; the runs and their outcomes are counted in \Cref{sec:results-faithful}.

\paragraph{Reproducing the Results.}
\label{app:software-regenerate}
Install the package, then run a quick example and a campaign according to the instructions provided in the \texttt{README.md}
Records gather into \texttt{summary.csv} and can be visualised by the provided notebooks.
